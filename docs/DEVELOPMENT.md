# Локальная разработка

## Требования и сборка

Node.js 22.11 или новее, JDK 21, Android SDK Platform 37, Build Tools 37.0.0, NDK 28.2.13676358. Демо ориентировано на Android-планшет. Основа нативного приложения — React Native 0.88.1. Зафиксированные версии зависимостей находятся в `package-lock.json`.

```sh
npm ci
npm run typecheck
npm test
npm run lint
npm run android:build
```

Укажите установленный Android SDK в локальном `android/local.properties` как `sdk.dir=/absolute/path/to/Android/sdk` либо задайте `ANDROID_HOME`. Отладочная подпись создаётся локально. Самостоятельный APK включает JavaScript и работает без Metro. Нативные зависимости и инструменты Android загружаются при первой сборке.

## Поток контроля качества

При первом запуске создаются имя локального инспектора и шестизначный PIN. При последующих входах используется этот профиль. PIN обрабатывается нативным адаптером; профиль не связан с сервером пользователей. Очистка данных приложения удаляет локальный профиль, осмотры и фотографии.

В разделе контроля выберите заказ либо складскую партию, просмотрите карточку документа и начните осмотр. Заполните количество, маркировку, размеры и влажность образца. Дата обработки выбирается через нативный календарь Android; будущая дата недопустима. Для каждого критерия укажите результат. Несоответствие требует причины из списка либо комментария. Фотография снимается системной камерой Android и получает категорию и необязательную подпись. Галерея конкретного критерия показывает связанные с ним снимки; раздел «Фото» объединяет их по категориям. Для подписания нужны заполненные данные, ответы на все критерии и хотя бы одна фотография.

Допуск дополнительно требует отсутствия несоответствий и попадания измерений в учебный профиль. Для задержки нужно заключение инспектора. После подписания данные осмотра становятся доступны только для чтения. Повторная оценка создаётся новым осмотром. PDF формируется из подписанного снимка: паспорт, таблицы измерений и проверок, заключение и фотографии по категориям. Длинные таблицы продолжаются на следующих страницах с повторением контекста. PDF открывается во встроенном просмотрщике; передача и печать выполняются через системные окна Android. Печать требует установленного пользователем Android Print Service; сетевые адреса принтеров в приложение не зашиты.

Отгрузка требует последнего подписанного допуска, относящегося к актуальному составу заказа. Подписанная задержка отменяет действие более раннего допуска. Изменение проверяемого количества, состава или состояния связанной партии требует нового контроля. Незавершённый черновик сам по себе не заменяет последнее подписанное решение.

## Архитектурные границы

- `src/app` собирает приложение, локальную сессию, типизированные маршруты React Navigation и Redux Toolkit. Redux содержит сохранённый снимок, статус операций и ошибки. Контроллер склада выполняет команды в очереди и передаёт Redux снимок после успешной записи.
- `src/features` группирует экраны по сценариям. Реестр документов, карточка заказа и этапы осмотра разделены на компоненты. Хук редактора ведёт черновик, а Reanimated меняет выделение активного этапа с учётом системной настройки анимации.
- `src/shared/ui` содержит общие поля, кнопки, варианты выбора, значки и тему.
- `src/quality/engine.ts` проверяет команды, полноту данных, измерения, неизменяемость подписанного осмотра и актуальность допуска. Профиль и состав объекта сохраняются вместе с осмотром.
- `src/data` сохраняет склад, осмотры, журнал и очередь обмена единым снимком. Снимок прежнего формата мигрирует с сохранением складских данных; вложенные данные осмотров проверяются при загрузке.
- `src/quality/report.ts` готовит текст и типизированные данные PDF. Имена файлов вложений проверяются, произвольные пути в нативный экспорт не передаются.
- `src/device/native.ts` связывает TypeScript с адаптером Android. Адаптер открывает системную камеру и календарь, сохраняет обработанные фотографии в каталоге приложения, создаёт PDF и выдаёт временный доступ через `FileProvider`.
- `src/device/scanner.ts` содержит `ScannerInputPort` и `KeyboardScanner`. Адаптер объединяет фрагменты строки до CR/LF, игнорирует пустой ввод, отбрасывает повреждённые и слишком длинные строки. Это интерфейс для дальнейшей интеграции: чтение USB, HID или последовательного порта не реализовано.

На устройстве должно быть доступно приложение камеры. Отмена съёмки или календаря возвращает пользователя к осмотру. Отсутствие камеры, ошибка сохранения или недоступное вложение выводятся как ошибка операции. Снимки повторно кодируются в JPEG; исходные метаданные камеры не включаются в сохранённую фотографию. PDF использует фотографии из хранилища приложения, а не произвольные внешние файлы.

## Проверки JavaScript и Android

Jest проверяет складские переходы, сохранение и восстановление, очередь обмена, а также создание осмотра, обязательные поля, пределы измерений, подпись, актуальность допуска, миграцию и повреждённые снимки. Отдельные тесты проверяют ввод сканера, содержимое отчёта, имена вложений, экран входа и интерфейс осмотра.

Нативные правила проверяются JVM-тестами:

```sh
cd android
./gradlew :app:testDebugUnitTest -PreactNativeArchitectures=arm64-v8a
cd ..
```

Тесты `DeviceRulesTest` проверяют правила PIN и ограничения попыток, имена файлов, даты и ограничение размеров изображений. `ReportPageLayoutTest` проверяет масштаб PDF и ограничение размера bitmap; `ReportFlowTest` — переносы длинных строк и сохранение контекста таблиц; `RasterPrintDocumentTest` — диапазоны страниц и ограничение памяти при печати. Инструментальный `ReportDocumentWriterTest` создаёт настоящий PDF с длинными комментариями и фотографиями. Они дополняют проверку интерфейса на Android и не заменяют запуск камеры, календаря и PDF на устройстве.

```sh
npm run e2e:build
DETOX_AVD=WoodlandReview npm run e2e
```

Конфигурация рассчитана на ARM64 Android-планшет с экраном примерно 1600×1024. Создайте AVD на основе установленного системного образа либо задайте имя существующего планшета через `DETOX_AVD`. Сценарии начинают с чистых демонстрационных данных. Полный набор включает два складских сценария и два сценария контроля до заключения и PDF, а также проверку альбомной компоновки при масштабе шрифта 1.3 и открытой клавиатуре; успешный допуск завершается отгрузкой. Для запуска на уже работающем планшете: `DETOX_DEVICE=emulator-5582 npx detox test -c android.attached`. Для воспроизводимого запуска камеры можно передать эмулятору `-camera-back emulated -camera-front emulated`; это тестовый кадр Android, не реальная древесина. Камерный помощник рассчитан на системную AOSP Camera Android 13.

Для просмотра на устройстве важны оба решения: заполненный осмотр с допуском и PDF, а также осмотр с дефектом и задержкой. Проверьте отмену съёмки, выбор даты, блокировку редактирования после подписи, сохранение после перезапуска и запрет отгрузки при отсутствии актуального допуска. Просмотрите созданный PDF, включая переносы текста и фотографии.

В сценариях контроля также проверяется системное окно печати с отменой; физическое задание не отправляется. Помощник AOSP Camera ждёт активной кнопки со стабильной геометрией и возвращает синхронизацию Detox после появления сохранённого вложения. При нестабильной аппаратной графике Apple Silicon для локального просмотра использовались параметры эмулятора `-gpu swiftshader -feature -Vulkan`.

## Границы демоверсии

На планшете выделено до 128 МиБ для обработанных снимков и до 64 МиБ для PDF. Если убрать фотографию из осмотра, файл продолжает занимать место. Повторный экспорт того же подписанного осмотра возвращает сохранённый PDF. При достижении предела приложение сообщает об ошибке записи и сохраняет существующие вложения.

Критерии и диапазоны — авторский учебный пример, а не нормативная методика приёмки. Для партии используется её демонстрационный профиль. Для заказа профиль измерений выбирается по первому артикулу и явно помечен как контрольный образец: одна запись размеров и влажности не подтверждает измерение каждой позиции или каждого изделия. Количество хранится в целых штуках, кубатура автоматически не вычисляется.

Подпись фиксирует локальное имя инспектора, время и решение. PIN — локальный демонстрационный барьер доступа; удалённая проверка личности, управление ролями и восстановление учётной записи отсутствуют. Формирование PDF не добавляет криптографическую подпись.

Обмен моделируется на том же устройстве. При конфликте операция остаётся в очереди; после переключения симулятора в состояние «Доступен» отправку можно повторить. Многопользовательский сервер и аппаратные драйверы сканера требуют отдельной реализации.

Состояние хранится одним JSON-снимком через AsyncStorage. Последовательная очередь предотвращает потерю обновлений внутри одного экземпляра контроллера; формат рассчитан на небольшие демонстрационные объёмы. Фотографии и PDF хранятся отдельно в частных каталогах приложения.
